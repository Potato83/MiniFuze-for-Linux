# Native packages / Установка через пакетный менеджер

Releases 0.1.0 and 0.1.1 include application packages for **Ubuntu 24.04 amd64**,
**Arch Linux x86_64** and **CachyOS x86_64**, plus a separate optional
**minifuze2-ctl-dkms 0.2.0** package. Source bundles contain AUR-ready recipes;
they have not been submitted to AUR. There is no project APT/pacman repository
yet: download local packages from GitHub Releases. Automatic package-manager
updates will require a repository or published AUR recipes in a later step.

Бинарные пакеты Arch и CachyOS собраны отдельно с обычной целью x86-64.
Используй пакет своей системы: версии OpenSSL и других библиотек могут
различаться. Обнови систему целиком перед установкой. Пакеты сообщают менеджеру
зависимости; он установит нужные библиотеки из репозиториев дистрибутива.
Пакеты Ubuntu предназначены для 24.04, поддержка Debian ими не заявляется.

## Новая установка

Скачай нужный пакет и его файл `.sha256` из одного релиза. Например:

```sh
sha256sum -c minifuze2-0.1.1-1-cachyos-x86_64.pkg.tar.zst.sha256
sudo pacman -U ./minifuze2-0.1.1-1-cachyos-x86_64.pkg.tar.zst
```

Для Arch используй `minifuze2-0.1.1-1-arch-linux-x86_64.pkg.tar.zst`.
Для Ubuntu 24.04:

```sh
sha256sum -c minifuze2_0.1.1-1_amd64.deb.sha256
sudo apt install ./minifuze2_0.1.1-1_amd64.deb
```

Запусти **MiniFuse 2 for Linux** из меню. Системная пользовательская служба
запускается окном по требованию. Для запуска после каждого входа:

```sh
systemctl --user daemon-reload
systemctl --user enable --now minifuze2.service
```

Установка или обновление пакета не запускает и не перезапускает микшер.
После обновления закрой окно, выполни `systemctl --user daemon-reload`, затем
`systemctl --user restart minifuze2.service` и открой окно. При этом звук
кратко прервётся. Файлы настроек остаются у пользователя:
`${XDG_STATE_HOME:-$HOME/.local/state}/minifuze2/` и
`${XDG_CONFIG_HOME:-$HOME/.config}/minifuze2/`.

## Аппаратные кнопки и индикаторы

Обычный USB-звук работает через ALSA. Для дополнительных функций установи
**отдельный** пакет модуля и заголовки своего ядра. Например для CachyOS:

```sh
sudo pacman -S --needed linux-cachyos-headers
sha256sum -c minifuze2-ctl-dkms-0.2.0-1-any.pkg.tar.zst.sha256
sudo pacman -U ./minifuze2-ctl-dkms-0.2.0-1-any.pkg.tar.zst
```

Для Arch с обычным ядром нужны `linux-headers`, для LTS — `linux-lts-headers`;
название пакета должно соответствовать ядру. Для Ubuntu с обычным generic:

```sh
sudo apt install linux-headers-generic
sha256sum -c minifuze2-ctl-dkms_0.2.0-1_all.deb.sha256
sudo apt install ./minifuze2-ctl-dkms_0.2.0-1_all.deb
```

После обновления ядра убедись, что DKMS собрал модуль для нового ядра.
Установив пакет, подключи **одну** MiniFuse 2 и выполни:

```sh
minifuze2-ctl-setup --user "$USER" --dry-run
sudo minifuze2-ctl-setup --user "$USER"
```

Команда определит серийный номер, запишет выбор карты и автозагрузку модуля,
настроит доступ и загрузит модуль, если он ещё не работает. При нескольких
MiniFuse укажи `--serial USB_SERIAL`. Серийный номер не печатается в отчёте.
Существующий другой выбор карты команда оставит для ручного разбора. Она
не выгружает работающий модуль, не перезапускает PipeWire и не переключает
+48V/INST. Новая группа применяется после повторного входа; активный локальный
сеанс также может получить доступ через udev. Подробнее — [установка](installation.md).

## Переход с установки через скрипты

### Приложение

Старые файлы в `~/.local/bin`, пользовательское меню и unit в
`~/.config/systemd/user` имеют приоритет над пакетными файлами. Одной установки
пакета недостаточно для перехода на его бинарники и службу.

1. Скачай и проверь новый пакет. Сделай резервную копию каталогов состояния и
   настроек выше, а также пользовательского unit, если менял его вручную.
2. Закрой окно. Из старого дерева исходников выполни от обычного пользователя
   `bash tools/install_desktop.sh --uninstall`. Установщик проверит принадлежность
   файлов, остановит свою службу и сохранит пресеты. Если файлы изменены или
   manifest отсутствует, остановись и разбери расхождения; не удаляй их вслепую.
3. Установи системный пакет, выполни `systemctl --user daemon-reload`, затем
   `hash -r`. Проверь `command -v minifuze2`: ожидается `/usr/bin/minifuze2`.
   `systemctl --user cat minifuze2.service` должен показывать пакетный unit.
4. Открой окно или включи службу командой выше. Проверь выбранную карту и микс.

Если прежняя установка использует `--reuse-existing` или исследовательскую
`minifuze-linux.service`, сначала сохрани её unit и пути состояния и останови
ту службу отдельно. Два микшера одновременно запускать не следует. Пакет
автоматически читает обычное состояние `minifuze2`, но не переносит частные
пути старого исследовательского сервиса.

### Модуль, ранее установленный вручную через DKMS

Переход приложения можно выполнить **без замены работающего модуля 0.2.0**.
Ручной и пакетный DKMS используют одинаковый каталог
`/usr/src/minifuze2-ctl-0.2.0`, поэтому не устанавливай пакет поверх ручных
файлов с `--overwrite` или `--force-overwrite`.

Перед отдельным переходом модуля сохрани `/usr/src/minifuze2-ctl-0.2.0`,
`/var/lib/dkms/minifuze2-ctl/0.2.0`, вывод `dkms status`, настройки
`/etc/modprobe.d/minifuze2-ctl.conf`, `/etc/modules-load.d/minifuze2-ctl.conf`
и старое правило `/etc/udev/rules.d/70-minifuze2ctl.rules` в приватную резервную
копию. В настройках есть серийный номер — не прикладывай их к публичному issue.
Убедись через `pacman -Qo` или `dpkg-query -S`, что каталог исходников ещё не
принадлежит другому пакету, а через
`modinfo -k "$(uname -r)" -n minifuze2_ctl` — что доступна сборка для текущего ядра.

В согласованное окно обслуживания: удали только эту регистрацию командой
`sudo dkms remove -m minifuze2-ctl -v 0.2.0 --all`, перенеси оставшийся каталог
исходников в резервную копию и установи пакет DKMS. Не выгружай работающий
модуль. Проверь новый `dkms status` и `modinfo` для текущего и следующего ядра
**до перезагрузки**. Если сборка не удалась, восстанови исходники из копии,
снова выполни `dkms add/build/install` для нужных ядер и проверь результат.
Не перезагружайся в ядро без готового модуля, если нужны аппаратные кнопки.

Существующие файлы выбора и автозагрузки в `/etc` сохраняются. Старое udev-правило
в `/etc` перекрывает пакетное правило с тем же именем в `/usr/lib`: сравни их
и архивируй прежнее правило только после проверки, что доступ сохранится.
Затем запусти setup с `--dry-run`. Переход ручного DKMS на физическом ноутбуке
в рамках подготовки пакетов автоматически не выполняется.

## Удаление

Закрой окно и останови службу: `systemctl --user disable --now minifuze2.service`.
Затем `sudo pacman -R minifuze2` или `sudo apt remove minifuze2`.
Модуль удаляется отдельно по имени `minifuze2-ctl-dkms`. Настройки пользователя
и созданные setup-файлы в `/etc` сохраняются. Удаление DKMS не выгружает модуль,
уже работающий в памяти. Перед его удалением из автозагрузки или выгрузкой
заверши работу клиентов управления.

## Сборка и происхождение пакетов

Пакеты 0.1.0 используют исходники неизменного тега `v0.1.0`, коммит
`676bec2bccc08bfa7ef6f645e5d09cfc6f1b3539`, с проверкой SHA256. Для 0.1.1 исходная ревизия и её SHA256 указаны в `packaging/native/upstream.json` и метаданных каждого пакета. Рецепты упаковки
добавлены отдельно, поэтому `BUILD-INFO.json` пакета записывает **оба** коммита:
исходники приложения и ревизию упаковки. Ранее подготовленные исходный и
бинарный архивы релиза сохраняются. Пакеты не содержат готового `.ko`, серийного
номера, пользовательского микса или автоматического включения +48V.

```sh
python3 tools/package_native.py arch --platform arch-linux
python3 tools/package_native.py arch --platform cachyos
python3 tools/package_native.py deb
```

Собирай в соответствующей системе с зависимостями из
`.github/workflows/native-packages.yml`; `makepkg` запускается без root.
Для извлечения рецептов без сборки:
`python3 tools/package_native.py arch-recipes --output-dir /tmp/minifuze-recipes`.
Каталог назначения должен быть новым. AUR-подобные `.src.tar.gz` можно
распаковать и собрать обычным `makepkg -si` после просмотра рецепта.
Рецепты получают исходники по закреплённому коммиту и проверяют их хеш.
