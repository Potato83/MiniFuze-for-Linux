# MiniFuse 2 for Linux

[Скачать 0.1.0-rc.1](https://github.com/Potato83/MiniFuze-for-Linux/releases/tag/v0.1.0-rc.1)
— исходники и сборка для Ubuntu 24.04 x86_64 с контрольными суммами SHA256.

** Я сделал  это с ИИ, в первую очередь для личного пользования**

Независимая панель управления Arturia MiniFuse 2 для Linux. Окно и аудиослужба
написаны на C; для окна используются GTK 4 и libsoup. Браузер и Python для
работы приложения не нужны. Закрытие окна оставляет звук и микс работающими.

Сейчас это предварительная версия **0.1.0-rc.1** с русским интерфейсом.
Работают три программных микса, уровни/панорама/Mute, аппаратные переключатели,
индикаторы, пресеты, настройки частоты и буфера. Добавлены Solo, Mute общего
выхода, Dim −20 dB, точный ввод уровня и отмена/повтор последних 32 изменений.
Имена, связь входов и скрытие виртуальных полос работают без импорта `.mfp`.
Новые функции прошли программные проверки и тест через физическую перемычку
OUTPUT L → INPUT 2 на 48 кГц. Проверены возврат USB и обновление службы;
прослушивание и обычная работа в DAW ещё требуют приёмки. MIDI DIN, обновление прошивки
и остальные непроверенные режимы перечислены в [TODO.md](TODO.md).

## Совместимость систем

| Система | Статус |
| --- | --- |
| CachyOS, x86_64, ядро 7.3.1-1-cachyos, PipeWire 1.6.10, MiniFuse 2 с прошивкой 1.5.0 | Кандидат собран и измерен на одном физическом устройстве |
| Ubuntu 24.04 | Сборка, изолированные программные/GTK-тесты и компиляция модуля в CI прошли; физическая MiniFuse не проверялась |
| Другие дистрибутивы Linux | Приложение должно собираться при наличии зависимостей ниже, но работу карты, установщика и модуля ядра нужно проверять на каждом дистрибутиве |
| Windows и macOS | Не поддерживаются |

Сам GTK доступен для [Windows и macOS](https://docs.gtk.org/gtk4/), но звуковой
движок и работа с устройством зависят от Linux
[PipeWire](https://pipewire.org/)/ALSA, системных интерфейсов Linux и отдельного
модуля ядра, который собирается с заголовками целевого ядра
([документация ядра](https://docs.kernel.org/kbuild/modules.html)). Установщик также использует
пользовательские службы systemd и udev. Одного переноса окна недостаточно,
чтобы приложение заработало в другой ОС. Исходники можно пересобрать для
другого Linux; готовые бинарники предназначены для той Linux-системы, где их
собрали.

## Сборка и запуск

Зависимости: компилятор C, make, pkg-config, GTK 4.12+, libsoup 3, json-c,
libmicrohttpd, OpenSSL, PipeWire с утилитами и WirePlumber.

```sh
make -j2
bash tools/install_desktop.sh
```

Запускай установщик от обычного пользователя. После установки приложение
появится в меню как **MiniFuse 2 for Linux**. На первом запуске выбери карту
и нажми «Подключить к микшеру». Для аппаратных кнопок нужен отдельный модуль
`minifuze2_ctl` — см. [установку](docs/installation.md).

Если уже работает старая исследовательская панель:

```sh
bash tools/install_desktop.sh --reuse-existing
```

Так окно подключается к существующей службе. Установка не заменяет её движок,
не меняет модуль ядра и не запускает второй микшер. Можно передать
`--ready-file` с абсолютным путём к файлу адреса старой панели.

Основная компоновка — компактный студийный микшер с закреплённым общим
выходом справа. Аппаратные кнопки находятся внизу; выбор карты и loopback —
в меню «Устройство». Новая установка использует тёмную тему; существующий
выбор оформления сохраняется.

«Пресеты → Сохранить как…» создаёт переносимый Linux-файл `.json` со всеми
тремя миксами, именами, связями и Solo/Dim/Mute. «Открыть пресет…» читает
`.json` и Windows `.mfp`. Аппаратные переключатели, выбор карты, частота и
буфер в эти файлы не входят. Экспорт `.mfp` сохраняет поля импортированного
Windows-шаблона; перед ним нужно выключить Solo, Dim и Mute общего выхода.

Уровень можно ввести числом и применить по Enter; двойной щелчок по фейдеру
или панораме сбрасывает значение. Ctrl+Z / Ctrl+Shift+Z отменяют и повторяют
программные изменения, Ctrl+S сохраняет микс, Ctrl+O открывает пресет.

Имена полос и миксов применяются по Enter. «Сохранить» записывает пресет;
несохранённый рабочий микс хранится отдельно. Частота и буфер общие для
PipeWire, поэтому на первом тесте оставь Auto. Перемычка для обычной музыки
и проверки окна не нужна.

Тему можно переключить в «Настройки → Оформление → Тема». Выбор применяется
сразу и сохраняется отдельно от микса в `$XDG_CONFIG_HOME/minifuze2/desktop.ini`
(обычно `~/.config/minifuze2/desktop.ini`). Переключение не прерывает звук.

Обновление установленной этим скриптом версии: закрой окно и выполни
`bash tools/install_desktop.sh --update`. Настройки и конфигурация службы
сохраняются; при ошибке команды обновления прежние файлы возвращаются.
Работающая служба микшера кратко остановится и запустится заново.
Затем открой окно снова.

Новая версия читает старые файлы 1–3 и сохраняет документ версии 4. Для
возврата на старую программу нужна резервная копия прежних настроек.

Удаление файлов приложения: `bash tools/install_desktop.sh --uninstall`.
Настройки и модуль ядра сохраняются.

## Перед публикацией

Правила для участников и выпуска: [CONTRIBUTING.md](CONTRIBUTING.md).
Список изменений: [CHANGELOG.md](CHANGELOG.md).

`make check` проверяет численные эталоны, входные данные и установщик в
отдельных каталогах. `tools/test_desktop.py` проверяет реальные GTK-элементы
на изолированном миксе без физических маршрутов.
Результаты локальных проверок кандидата: [отчёт](docs/validation/studio-rc1.md).
Компоновка и скриншоты обеих тем: [студийный интерфейс](docs/desktop-design.md).
Аппаратные измерения и повторение теста: [проверка MiniFuse](docs/hardware-validation.md).

`bash tools/package_release.sh` создаёт исходный архив в `dist/`;
`--binary` добавляет сборки для текущего Linux. Это не универсальный пакет:
на другой системе могут потребоваться зависимости и пересборка.
Скрипт ничего не публикует.

Подробный отчёт о реверсе с протоколом, моделью микшера, методикой проверок и
ограничениями доступен на русском и английском:
[русская версия](docs/reverse-engineering.ru.md),
[English version](docs/reverse-engineering.md).
Полное описание проекта и зависимости: [README.md](README.md).

Тег, совпадающий с `v` + содержимое `VERSION`, публикует GitHub prerelease
после успешных проверок приложения и сборки модуля ядра.
К релизу прикладываются исходники, бинарный архив для Ubuntu 24.04 x86_64
и контрольные суммы. Оставшаяся приёмка до стабильной версии перечислена
в [TODO.md](TODO.md). [Изменения кандидата](docs/release-notes.md).
